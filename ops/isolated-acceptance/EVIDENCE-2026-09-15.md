returned 403/1010 for urllib's default User-Agent. Their empty-payload POST
returned 400 with an explicit User-Agent (no message posted), and GET returned
200 instead of 403 on two networks. The earlier drop-in finding was a separate
bug. These endpoint observations are owner-reported, not independently repeated
with a production webhook here.

Independent verification used Python 3.12.3 and the real `http_post_json` in a
network-isolated container with a local HTTP receiver: before the change it
sent `Python-urllib/3.12`; afterward it sent
`DiscordBot (https://github.com/Pareton-ai/pareton, 1.0) pareton-deploy-notifier/1.0`.
This follows [Discord's documented User-Agent format](https://docs.discord.com/developers/reference#user-agent).

The new unit regression patches only `urlopen`, preserving real request
construction. It failed on the old implementation because the explicit header
was absent, then passed after the fix. Updated stage-1 ops suite: **39 passed**;
changed-file Ruff checks and independent review passed. The earlier 28-assertion
systemd/Vector run was not repeated for this HTTP-header-only change.
